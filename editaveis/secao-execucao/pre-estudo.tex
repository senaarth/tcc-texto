\subsection{Pré-estudo da Hipótese Escolhida}
\label{subsec:pre-estudo}

Uma vez escolhida a suposição a ser avaliada, a equipe decidiu qual seria a versão de tratamento, o filtro de nível de difículdade se tornaria o quarto da lista, deixando, assim, de ser o último. Essa escolha não foi arbitrária, mas sim advinda de decisões de negócio, levando em consideração a importância dos três primeiros filtros para determinados fluxos de uso da funcionalidade. 

Além da versão de tratamento (variável independente), também foram definidas as variáveis dependentes do experimento. Estas, foram escolhidas para refletir a usabilidade de cada versão. Primeiro, o número de vezes que cada usuário utilizou a funcionalidade, visando caracterizar a satisfação dos usuários através da subcaracterística de utilidade; segundo, o numero de questões por atividade criada, tratando da eficácia na seleção de questões; e, por fim, também contemplando a eficáceia, o número de atividades criadas por usuário durante o período.

Como já descrito na subseção \ref{subsubsec:variants}, as populações do experimento surgem da divisão da base de usuários em usuários beta e usuários não beta. Esta forma se apresentou como uma alternativa viável e pertinente ao experimento, já que faz parte de um processo padronizado na empresa. Os usuários beta então, são aqueles submetidos a versão de tratamento, já o resto da base, por sua vez, utilizará a versão de controle, não havendo alteração na ordem dos filtros para estes. Vale ressaltar que, as escolas beta têm ciência de que recebem versões do produto que podem não estar prontas para produção ou utilização por toda a base, mas, apesar disso, nenhum docente foi avisado de que estavam sendo apresentados uma versão experimental da ordenação dos filtros.

Definidos os sujeitos e variáveis, antes do desenvolvimento da nova versão, foi realizado um pré-estudo do experimento: dados de uso da plataforma, referentes à criação de atividades e a utilização dos filtros foram coletados durante o período de duas semanas. Estes dados serviram para realização de testes A/A, necessários para verificar a similaridade do comportamento entre as populações de usuário. Esta similaridade trouxe uma segurança para o prosseguimento com o experimento, já que, no caso de um posterior experimento onde o comportamento dos usuários se diferencie, é previamente sabido de que essa diferença não era existente antes da utilização da versão de tratamento por parte dos usuários beta.

Esse procedimento foi realizado durante duas semanas (do dia 08 até o dia 21 de outubro de 2024). Foram coletados 41516 eventos (sinais de uso) referente ao uso de filtros na seleção de exercícios de 2864 usuários únicos (destes, 401 utilizando a versão de tratamento, ou seja, 14\%). Estes dados foram tratados de forma que a categoria de cada utilização de algum filtro foi computada e separada para cada usuário único. Desta forma, foi possível verificar quantos usuários que utilizaram algum filtro no período, escolheram alguma vez sequer a opção de nível de dificuldade. Por se tratar de uma variável categórica, foi utilizado o teste chi-quadrado para testar a diferença da mesma entre as populações. O teste apontou não haver diferença com um p-valor de aproximadamente 0.94, o resultado é aprensentado na Figura \ref{fig:pre-study-adocao}.

\subsection{Planejamento do Experimento}

Como citado na seção anterior, para se analisar a qualidade em uso das diferentes versões, foram escolhidas medidas que refletissem as características deste aspecto de qualidade. Porém, para ser possível ponderar sobre os resultados, foi utilizado o modelo de análise QATCH \cite{qatch}. Os autores propõe a hierarquização das métricas sendo avaliadas com relação aos seus níveis de importância relativas entre si, a fim de se definir pesos diferentes para cada aspecto sendo avaliado. Este procedimento é feito através do método AHP \cite{ahp} (este, é explicado na Subseção \ref{subsec:ahp}). A hierarquização das características pode ser observada na Figura \ref{fig:qatch_experiment}, bem como as importâncias relativas nas Tabela \ref{tab:ahp-metrics} e \ref{tab:ahp-characteristics}.

As tabelas mostram a importância relativa entre as métricas e as características, respectivamente. Os valores são provenientes de discussões dos colaboradores envolvidos em relação contexto sendo avaliado. Esta discussão permite definir pesos quantiativos para cada métrica coletada de forma flexível e adaptada ao contexto do produto e da funcionalidade.

A Tabela \ref{tab:ahp-metrics} mostra que, com média certeza, o número de listas criadas é muito mais importante que o número de exercícios selecionados. Já a Tabela \ref{tab:ahp-characteristics} mostra que a satisfação, com média certeza é moderadamente mais importante que a eficácia no contexto sendo observado. Não há uma tabela para métricas de satisfação pois será observada apenas uma, o número de usos do filtro (estes valores de importância e de certeza provêm do método AHP, apresentado na subseção \ref{subsec:ahp}).

Uma vez definidas as importâncias relativas, é possível definir o peso quantiativo de cada métrica e característica, para posterior agregação dos dados coletados em um indicador único. Este cálculo se dá primeiro pela normalização das métricas coletadas, já que é necessário que os valores sejam represetados entre 0 e 1. Após este procedimento, as métricas devem ser múltiplicadas pelo seu peso e somadas, gerando o escore de sua respectiva característica/subcaracterística.

Uma vez realizado este processo, o mesmo é feito à nível de subcaracterística, afim de gerar um indicador para a característica (não há necessidade de normalização neste passo, já que já foi realizada no anterior). Com os valores de característica, estes são múltiplicados pelos seus pesos e somados para gerar um indicador único de qualidade em uso. Este processo pode ser representado pelas seguintes fórmulas:

\[
Q = w_{satisfacao}q_{satisfacao} + w_{eficacia}q_{eficacia};
\]

\[
q_{eficacia} = w_{listas}q_{listas} + w_{exercicios}q_{exercicios};
\]

\[
q_{satisfacao} = q_{usos}.
\]

\noindent
Onde:

\begin{itemize}
    \item \( Q \): é o indicador de qualidade em uso;
    \item \( w_{x} \): é o peso da característica/subcaracterística/métrica \textit{x};
    \item \( q_{x} \): é o valor normalizado encontrado/calculado da característica/subcaracterística/métrica \textit{x};
\end{itemize}

Esta agregação deve resultar em um valor entre 0 e 1, servindo para indicar uma pontuação referente à qualidade em uso. Este cálculo será realizado para cada usuário. Realizado este processo, serão separados em seus respectivos grupos,  sendo possível comparar a qualidade em uso das versões analisadas. Sendo assim, as hipóteses do experimento serão:

\begin{itemize}
    \item \(H_0\) Não há diferença na percepção de qualidade em uso entre as versões A e B (\(\mu Q_a = \mu Qb\));
    \item \(H_1\) A percepção da qualidade em uso é maior na versão A quando comparada a versão B (\(\mu Q_a > \mu Qb\));
    \item \(H_2\) A percepção da qualidade em uso é maior na versão B quando comparada a versão A (\(\mu Q_a < \mu Qb\)).
\end{itemize}

\noindent
Onde: 

\begin{itemize}
    \item \(\mu\) é a média;
    \item \textit{\(Q_x\)} é o indicador de qualidade em uso da versão x.
\end{itemize}

Definidas as hipóteses do experimento o próximo passo é a coleta e análise dos dados. Para mitigar erros estatísticos, serão tomadas as seguintes medidas:


\begin{itemize}
    \item \textbf{Erro tipo I}: será definido um nível de significância alfa de 5\% para os testes de hipótese realizados, a fim de evitar a rejeição da hipótese nula erroneamente;
    \item \textbf{Erro tipo II}: os conjuntos de dados serão aumentados se necessário, afim de se aumentar também o poder estatístico de teste. Ou seja, os dados serão coletados durante um determinado período e, caso os testes se demonstrem inconclusivos por alguma razão, esse período será extendido iterativamente;
\end{itemize}
